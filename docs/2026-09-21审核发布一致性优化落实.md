# 2026-09-21 审核发布一致性优化落实

## 本批范围

本批实施《项目最新情况、优化方向与预计成果》中的 O03：统一文字、归属、图片和公开服务使用的审核版本。没有实施 O04 的公网请求预算、队列或限流，也没有改变回答边界策略，因此策略版本仍为 `2026-09-21.3`。

## 已落实内容

- 增加不可变的文档、知识片段和图片发布快照。现有 `documents`、`chunks`、`media_assets` 作为当前运营草稿，公开检索只读取 `active_version` 指向的快照。
- 现有已审核发布资料在数据库初始化时自动迁移为 v1 快照，不需要重导文档；未发布草稿不会被迁移成公开版本。
- 修改标题、知识域、所属公司、品牌、产品标识、公开范围、证据类型、有效期、片段正文、片段启停、向量或图片设置时，内容与“待审核草稿”状态在同一数据库事务中更新。
- 草稿变更不再中断当前公开服务。只有“审核并发布”才会在一个事务内创建完整快照并切换 `active_version`；撤回通过独立状态立即停止公开检索。
- 发布、撤回、草稿变更和回滚写入 `publication_events`。管理页展示公开版本、当前草稿、历史版本和最近事件，并支持回滚公开快照；回滚不会覆盖较新的运营草稿。
- 公司与产品文字检索、图片列表及单张图片接口均强制过滤 `owner_company_id=wuxi-gougelila`，非本公司归属即使存在发布快照也不会进入公开回答。
- 图片发布时复制到 `data/published_media/<document>/<version>/`，避免重新提图或工作区文件变化覆盖已发布原图。
- 重新提图会报告新增、变化、缺失和未变化数量；同一 `image_key` 保持稳定资产 ID，并保留运营修改的 caption、alt text、产品标识和启用状态。原文重新提取的标题单独展示，不再覆盖运营标题。
- 图片新建、图片编辑和重新提取的变化默认为待审核；发布文档时才连同文字一起批准并切换。
- `effective_from`、`effective_to` 改为带时区时间输入，统一保存为 UTC，并验证开始时间不得晚于结束时间。
- 检索结果携带发布版本。模型生成和证据校验完成后，服务端再次确认文档仍是同一公开版本且未撤回；期间撤回、回滚或发布新版本时，本次回答降级为 `SOURCE_CHANGED_DURING_GENERATION`，不会继续发出旧证据。

## 固定回归结果

| 场景 | 当前结果 |
| --- | --- |
| 已发布文档修改片段或标题 | 当前公开快照继续服务，草稿进入 pending |
| 新草稿审核发布 | 文字、归属、片段和图片原子切换到新版本 |
| 草稿所属公司改为第三方 | 旧自有快照继续服务；第三方草稿不能由管理服务公开发布 |
| 底层存在非本公司发布快照 | 文字与图片公开查询均过滤 |
| 修改已发布图片 caption | 用户继续看到旧快照 caption，直到新版本发布 |
| 重新提取同一图片 | 运营 caption 保留，并显示提取差异 |
| 回滚历史版本 | 公开查询切回历史快照，当前草稿保留 |
| 模型生成期间撤回来源 | 回答不发出，返回 `SOURCE_CHANGED_DURING_GENERATION` |
| 有效期开始晚于结束 | 管理请求拒绝 |
