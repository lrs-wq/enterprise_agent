# 第三阶段：性能、资源隔离与分阶段指标

日期：2026-09-28。范围对应[优化路线](2026-09-21项目现状与优化路线.md)的第三阶段：O06、O04 后续和 O09 分阶段指标。本批只改开发目录，**未同步独立公网运行副本**，也未修改已发布知识内容。开发目录的通用养宠清洁用品安全守卫在回归中作了收紧。

## 做了什么

- 公司/产品回答不再要求模型输出会由服务端重建的 `thinking_summary`。短事实题与常规题采用不同生成预算；首轮提示约束为直接回答、少量分节、不主动添加用户未问的数字或规格。证据守卫、来源状态复核和一次受控修正仍完整保留。性能基准使用提示词版本 `2026-09-28.2`；最终版本 `2026-09-28.5` 后续只调整通用养宠提示，不改变公司/产品生成路径。
- 新增 `/api/chat/stream`：先发送真实的已接收、排队、主题判断、检索、生成、核验、修正进度，最后仅发送已校验的完整答案。页面使用该接口；原 `/api/chat` JSON 接口保留。浏览器取消会取消正在运行的模型任务。流响应设置 `no-store`；Nginx 配置也为该精确路径关闭缓冲、限制 64 KiB 请求体和 85 秒读取时限。不会预先展示未核验正文。
- 对无历史、无私人或时变内容的公开文本问答，缓存通过证据守卫的结果。键包含归一化问题、知识域、策略、模型、提示词版本、活动知识版本指纹和公开范围；命中时再次确认来源仍在活动版本。发布、回滚或撤回改变版本指纹或来源状态，不能继续命中旧答案。缓存为单进程 128 条、300 秒上限，不能跨 worker 共享，也不把上下文答案跨用户复用。
- 执行、等待容量从仅进程内计数扩展为同机 SQLite FIFO 租约队列，聊天、模型、后台任务和上传接收共用同一协调数据库。执行槽位定期续租，worker 异常退出后最多约 45 秒回收；队满立即拒绝。JSON 接口返回 HTTP 429，SSE 连接若已开始则发送带 `status=429` 的错误事件。该机制只适用于同机本地文件系统，不是跨主机分布式队列。现有按客户端限速仍是单进程状态，部署多个 worker 前仍需将限速也迁至共享状态或保持单 worker。
- 文档解析与图片提取改为隔离子进程，取消时终止其进程组（含 OCR 子进程）；结果通过本地 JSON 返回。图片先提取到临时目录，成功后再移入正式媒体目录，避免取消时直接留下半成品。数据库更新仍由主进程完成。
- `query_logs` 增加稳定来源快照、模型及提示词版本、主题判断、首轮生成、修正耗时/次数/原因、排队、总耗时和缓存命中。问题字段继续只存 SHA-256，不保存原始提问。新增固定题集基准脚本 `scripts/benchmark-latency.py`，每条记录立即落盘，支持中断后续跑。
- 全量评测人工抽查发现 QA-087（健康宠物洗澡）虽通过自动状态校验，回答末尾却混入无关的“参考食品包装”提示。原因是原通用养宠系统提示把喂食安全提醒写成了全局规则。最终版将“参考包装”只注入喂食量/饮食相关问题，不会因“喂食器清洁”中的“喂”字误触发；最终 v5 全量中的 QA-087 正文不含食品包装或喂养提醒。
- 首轮 272 条全量执行中，QA-068 的猫砂盆清洁回答因安全守卫拦截清洁剂内容后，修正模型返回无效结构而误拒；其他 271 条通过。现已补上降级路径：仅当首稿可删减为**重新通过完整安全守卫**的答案时，在修正超时、结构无效或修正后仍不安全时使用该答案；模型连接中断仍返回服务不可用，不伪装成功。第二轮又发现 QA-089（生活区通风清洁）首稿和修正稿均带医疗功效宣称时整句被删光而误拒；改为先保留安全整句，不足时才保留安全分句，并重新校验完整答案。两个失败分支都有先复现再修复的回归测试；最终 v5 全量中 QA-068、089 均正确回答。
- 抽查 QA-095 发现自动状态虽通过，却在反对“高浓度 84 消毒液清洁后立即使用”的同时夹带了稀释 84 的操作建议。原守卫把同一句后半段的“充分冲洗”当成了整句免责。最终版逐分句检查积极的化学品使用建议，明确禁用警示仍可通过；若需删减，只保留重新通过完整守卫的安全替代。模型提示也要求危险清洁品问题直接回答“不能”，不给稀释、喷洒等步骤。最终 v5 全量中的 QA-095 正文已人工核对，没有操作步骤。
- 抽查 QA-029 发现一个**非本批新增**的波动：问“所有喂食器都有摄像头吗”时，历史版与早期本轮可能回退为一条“带摄像头”的已审核产品原文，没有直接回答“是否全部”。最终 v5 全量这次区分了有/无摄像头型号，但现有全量执行器只自动核对状态、证据状态和原因码，未把用例表的长篇自然语言“必须/禁止包含”转成逐句断言。因此 272 条状态通过不能解释为逐题内容质量均已审核；回答完整度与自动语义评测仍是后续工作。

## 测量口径与结果

固定题集为 QA-001、002、004、009、012、021、022、027、030、040，涵盖公司介绍、品牌关系与产品功能。每轮使用相同 Mac、本地模型、同一源知识库的隔离 SQLite 副本；顺序运行，先热身一次，关闭答案缓存，正式每题重复 5 次。这里只测无并发的模型问答端到端时间，不把 SSE 首次反馈时间误算成完整回答时间；公网网络延迟和多用户负载另测。

| 版本 | 样本 | P50 | P95 | 发生修正 | 最终有据回答 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 改动前基线 | 50 | 27.86 秒 | 46.20 秒 | 38/50 | 50/50 |
| 第一候选（已停止） | 11/50 | 未作正式统计 | 未作正式统计 | 明显偏多 | 11/11 |
| 最终候选，无缓存 | 50 | 8.81 秒 | 20.60 秒 | 13/50 | 50/50 |
| 已校验公开缓存命中，单题重复 | 5 | 3 毫秒 | 3 毫秒 | 0/5 | 5/5 |

最终候选的无缓存 P50 比基线低 68.4%，P95 低 55.4%；二次修正从 38/50 降到 13/50。固定题集下两项分位数目标均达到，50 次最终均为 `grounded / supported`；但仍有 2/50 次超过 30 秒，最长 32.32 秒。缓存测量先热身生成一次，再对同一公开无上下文问题重复 5 次；3 毫秒是**服务函数本机耗时**，不是公网 HTTP 延迟或高并发承诺。第一候选虽然删掉多余输出字段，却让多个问题继续展开过多事实并触发修正，因此在 11 次后停止。基线、最终无缓存和缓存原始记录分别在 `outputs/第三阶段性能基线_2026-09-28.csv`、`outputs/第三阶段性能优化候选2_无缓存_2026-09-28.csv`、`outputs/第三阶段公开缓存命中_2026-09-28.csv`。由于目录尚非 Git 仓库，基线进程在代码编辑前启动，但缺少不可变构建标识；未来应由 O10 的版本化发布机制补齐这一可复现性缺口。

## 验证与限制

最终提示词版本 `2026-09-28.5` 的隔离全量回归 **272/272 状态通过、新增状态异常 0、执行异常 0**；原始结果见[最终 v5 CSV](../outputs/公司智能助手_第三阶段最终v5全量评测_2026-09-28.csv)，逐题问题与回复见[最终问答 Markdown](../outputs/公司智能助手_第三阶段最终问答结果_2026-09-28.md)。已额外人工核对 QA-029、087、089、095。自动化单测 325 项通过，`ruff check`、`ruff format --check`、`mypy src` 通过。该结论针对开发目录的隔离知识库与本地模型，不代表公网部署已验证。

自动测试覆盖跨实例及真实跨进程的 1/2/4 容量上限、排队取消、失效租约回收、隔离解析/提图、取消终止、SSE 进度与最终答案顺序、快速完成不等待心跳、请求体限制、缓存隔离与撤回失效。当前没有对公网执行冲击压测或发布；上线前需备份运行数据、核对 Nginx 不缓冲事件流、执行公网冒烟及断线取消测试。

缓存命中 ≤1 秒目标只适用于未排队、知识库正常可读的本机请求；缓存请求目前仍经过聊天执行槽位，忙时会排队。共享队列仅解决同机 worker 的总容量，不替代跨主机协调、共享限速、真实负载压测或隧道账户降权。
`data/runtime_capacity.db` 是可重建的运行态租约数据，不应当作知识库备份或跨主机复制；迁移、部署和重启时仍以 `data/knowledge.db` 的已审核版本为事实来源。
隔离子进程会增加小文件导入的启动开销，本批未对导入速度做基准。日志目前记录模型标签而非不可变权重摘要；与基线代码缺少 Git 标识一样，仍需后续发布版本管理补齐。
