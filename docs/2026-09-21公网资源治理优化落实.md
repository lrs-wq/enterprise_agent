## 2. 已实施内容

### 2.1 整个聊天请求共享一个截止时间

聊天默认总时限为 75 秒，从进入容量控制开始计时，覆盖排队、检索、首次生成、修正生成和最终校验。模型调用另有 65 秒时限，Embedding 调用为 90 秒；模型超时不会被伪装成普通的“证据不足”回答。

- 请求总时限耗尽：HTTP 504，`CHAT_DEADLINE_EXCEEDED`。
- 单次模型调用超时：HTTP 504，`MODEL_TIMEOUT`。
- 模型服务不可用：HTTP 503，`MODEL_UNAVAILABLE`。
- 所有可重试故障都使用结构化 `detail.code/message/retryable`，适用时返回 `Retry-After`。

### 2.2 保守并发与有界队列

当前设备从单路生成起步，不假设能稳定承载 4 路模型生成：

| 资源 | 同时执行 | 等待队列 | 队满行为 |
| --- | ---: | ---: | --- |
| 完整聊天请求 | 1 | 2 | HTTP 429 `CHAT_BUSY` |
| 本地模型调用 | 1 | 4 | 释放上层请求并返回忙碌/超时 |
| 后台解析、发布、重建索引等任务 | 1 | 1 | HTTP 429 `ADMIN_TASK_BUSY` |
| 上传接收 | 1 | 1 | HTTP 429 `UPLOAD_INGRESS_BUSY` |

容量状态通过 `/api/health` 暴露当前 `active/queued/max_active/max_queue`，便于判断是模型异常还是正常排队。聊天响应增加 `X-AI-Queue-State` 和 `Server-Timing`，响应体指标增加 `queue_ms` 与 `total_ms`。

这些限制是单进程内的保护，不是多机分布式队列。若以后启动多个 worker，必须改用共享容量与限速存储后再扩大实例数。

### 2.3 客户端取消会向上游传播

聊天页生成期间显示取消按钮。浏览器中止 Fetch 后，服务端读取 ASGI 断连事件、取消检索/模型协程并释放聊天和模型槽位；Ollama HTTP 请求随任务取消关闭。前端会删除未完成问题的会话历史，恢复输入和发送按钮。

解析器中通过线程执行的同步工作只能做到“停止等待结果”；底层线程可能继续到当前解析步骤或 OCR 时限结束。因此上传/OCR 同时还有独立并发和 280 秒任务预算，不能把客户端取消描述成对所有同步库的强制终止。

### 2.4 公开接口和管理员认证限速

- 公开聊天：同一客户端默认 60 秒最多 12 次；超限返回 HTTP 429 `CHAT_RATE_LIMITED`。
- 管理认证：同一客户端 300 秒内最多 5 次失败；达到上限返回 HTTP 429 `ADMIN_AUTH_RATE_LIMITED`。
- 正确令牌会清除该客户端已累计的失败事件。
- 仅当实际连接来自本机反向代理时才信任 `X-Forwarded-For`，避免公网直连伪造客户端地址。
- 支持 `AI_AGENT_ADMIN_PREVIOUS_TOKEN` 与带时区的到期时间，在换发新令牌时提供短暂双令牌窗口；当前部署没有启用旧令牌。

限速器同样位于单进程内，服务重启后计数清空。为避免大量一次性客户端地址导致内存键空间无限增长，当前最多跟踪 10,000 个客户端键，周期清理过期键，达到上限时淘汰最久未活动键。它用于当前单实例的即时保护，不替代 Nginx/Redis 级跨实例限速。

### 2.5 上传与解析在消耗资源前受限

请求体中间件既检查 `Content-Length`，也在分块请求到达时累计字节，避免只依赖客户端声明。上传文件按 1 MiB 分块复制并在复制过程中检查大小，不再等完整临时文件写完后才拒绝。

| 限制项 | 当前默认值 |
| --- | ---: |
| 聊天请求体 | 64 KiB |
| 单次上传请求体 / 单文件 | 100 MiB |
| 单次上传文件数 | 5 |
| PDF 页数 | 300 |
| OCR 处理时间 | 240 秒 |
| XLS/XLSX/CSV 总行数 | 50,000 |
| Office ZIP 解压后总量 | 256 MiB |
| Office ZIP 成员数 | 5,000 |
| 单文档最大知识片段 | 20,000 |
| 后台任务总时限 | 280 秒 |

XLSX 在解析文字或图片前都会检查 ZIP 成员数和声明的解压后体积；PDF 文字解析、页图提取和 OCR 共用页数边界。以上是资源治理，不是病毒扫描或完整沙箱，宏、恶意解析器漏洞和 MIME 深度检测仍需在后续生产安全阶段处理。

### 2.6 代理和页面反馈对齐

- Nginx 为精确的 `/company-ai/api/chat` 路径设置 64 KiB 请求体、85 秒读取时限和 15 秒发送时限；应用在 75 秒停止工作，代理留 10 秒交付 JSON。
- 其他 `/company-ai/` 管理路径保持 100 MiB 和 300 秒，以覆盖应用 280 秒后台任务预算。
- 前端区分排队/处理中、忙碌、超时、网络故障和用户取消；读取结构化错误及 `Retry-After`。
- 当前仍是最终 JSON 一次性返回。页面在 0.8 秒后只展示真实的概括状态“检索、生成并核验证据”，不会流出尚未通过守卫的模型正文。

## 3. 验证结果

所有并发与超时实验都在实时运行库的一致性副本上执行，模型仍调用本机真实 Ollama；没有对公网做破坏性负载测试。

| 验证 | 结果 |
| --- | --- |
| 1/2/4 受控并发 | 第 1 个执行，第 2、3 个有界排队；第 4 个约 **1.243 ms** 返回 HTTP 429 |
| 取消释放 | 取消执行中与排队请求后约 **40 ms** 观察到聊天/模型容量归零 |
| 真实总时限 | 将隔离实例总时限设为 5 秒，长问题在 **5.002 s** 返回 HTTP 504；随后所有容量为 0 |
| 正常长问题 | 单路真实模型请求 **38.63 s** 完成，低于默认 75 秒总预算 |
| 请求体 | 无 `Content-Length` 的分块聊天请求超过上限后返回结构化 HTTP 413 |
| 公开限速 | 同一测试客户端前 12 次通过，第 13 次返回 HTTP 429 |
| 管理登录限速 | 同一测试客户端 4 次 HTTP 401，第 5 次起 HTTP 429；另一客户端正确令牌仍为 HTTP 200 |
| 页面取消 | 公网页面出现取消按钮；点击后恢复输入，显示取消结果，后端容量归零 |
| 公网冒烟 | 健康检查 200、快速对话 200、超大聊天请求由 Nginx 413 拦截 |

验证期间发现并修复了一个仅存在于候选实现中的问题：最初使用框架级 `is_disconnected()` 轮询会让已完成响应在部分 ASGI 中间件组合下滞留。最终改为对原始 `receive()` 的断连事件与业务任务做竞争等待；该候选版本未部署到线上。

## 4. 运行与故障契约

常见故障码：

| HTTP | 代码 | 含义 |
| ---: | --- | --- |
| 413 | `REQUEST_BODY_TOO_LARGE` / `UPLOAD_*_TOO_LARGE` | 请求或上传超限，不重试同一内容 |
| 429 | `CHAT_BUSY` / `CHAT_RATE_LIMITED` | 容量或频率超限，按 `Retry-After` 重试 |
| 429 | `ADMIN_TASK_BUSY` / `ADMIN_AUTH_RATE_LIMITED` | 后台任务繁忙或认证失败过多 |
| 503 | `MODEL_UNAVAILABLE` | Ollama 当前不可用 |
| 504 | `CHAT_DEADLINE_EXCEEDED` / `MODEL_TIMEOUT` | 总预算或模型调用超时 |

健康检查只能说明当前依赖和容量快照，不代表长期 SLA。判断性能需同时观察 `queue_ms`、`total_ms`、生成耗时、超时率和 429 比例。

## 5. 当前限制与后续工作

1. 当前容量门和限速器只适用于单进程；多 worker 或多机部署前需引入共享队列/令牌桶。
2. 同步 PDF/Excel 库通过线程执行，客户端取消是尽力而为；真正的强制终止需要隔离子进程或任务 worker。
3. 本次没有做 SSE、正文流式输出或答案缓存。O06 应先流真实状态，最终只发送通过校验的答案。
4. 只完成了小规模 1/2/4 受控实验，结论是保持单路模型生成；不能据此宣称 4 路并发可用，也不能把单次 38.63 秒视为 SLA。
5. 服务器隧道仍使用 root 账户，需改为仅允许反向转发的专用低权限账户，并补外部可用性监控。
6. Nginx 在请求体过大时会直接返回自己的 HTML 413；前端已降级为明确的 HTTP 413 故障提示。如需全链路统一 JSON，可后续配置代理错误页。
