# 2026-09-21 证据断言优化落实

## 本批范围

本批实施《项目最新情况、优化方向与预计成果》中的 O02：让引用真正支持具体事实。没有改动知识内容、审核发布模型、产品图片归属、并发控制或前端布局。

O02 属于生成后的证据守卫，不改变回答边界策略，因此策略版本仍为 `2026-09-21.3`。

## 已落实内容

- 将摘要和正文拆为具体断言逐条核验，不再只判断整段与若干来源拼接文本是否大致相似。
- 参数断言抽取数值、单位、条件、邻近型号和属性；支持 V、W、L/ml、mm/cm/m、kg/g、mAh、Hz、dB、面积、数量和时间等常见单位及换算。
- 专门核验“支持/不支持”“标配/选配”“部分/全部”等肯否方向和限定范围。
- 阻止同一证据片段内跨型号、跨属性搬用数值，也阻止把上限、下限和精确值互相替换。
- 检查标题、分节标题、正文和追问中的参数及边界内容；公开图片的 caption/alt text 也执行第三方和医疗边界检查。
- 每个结构化来源必须直接支持所在回答块中的至少一个断言；主题相关但没有具体支撑的多余来源会先被校验识别，局部删除后仍须重跑完整校验。
- 返回给用户的来源摘录改为直接支持断言的原文片段，不再默认展示候选片段开头。
- 首次校验失败后仍只允许一次受约束修正；修正步骤会收到失败字段与具体断言，并按错误类型要求改绑直接来源、恢复原文限定词或删除无证据内容。再次失败则降级为 `insufficient_evidence`。
- 编号列表不作为产品参数，避免把 `1.`、`2.`、`3.` 误判成需要在证据中逐值匹配的事实。

## 业务概述误拒现场修复

2026-09-21 的公网样本中，“工厂主要做什么业务”和“公司主要做什么业务？”
均已被正确路由为 `COMPANY_PUBLIC_ALLOWED`，并非回答边界分类失败。失败发生在
生成后的证据守卫：

- 发布资料中存在 `48000余平`、`2.3万m` 等口语化或 OCR 丢失平方符号的面积写法，
  生成端则可能写成“约 48000 平方米”或“2.3 万平方米”。原守卫将它们视为不同值。
- 资料中的“四大中心”、“三大品牌”与回答中的“4 大中心”、“3 大品牌”
  未做中文计数归一化。
- 模型有时会给一个回答块多挂一个相关但并未直接支持该块的来源，
  原流程在一次模型修正仍失败后会整个降级。

本次修复后：

- 面积别名、精确值到“约”的保守表达、OCR 面积单位和中文计数会归一化比较。
- “工厂总面积 48000 平方米”仍不能被改绑为“生产车间 48000 平方米”；
  这一错误会继续返回 `UNSUPPORTED_ATTRIBUTE_VALUE_BINDING`。
- 第二次生成仍只有局部断言失败时，服务端可删除该原子断言；只有多余来源时，
  只删除该回答块中未实际支持任何断言的来源。修正后必须再次通过原有完整校验，
  未知来源、边界内容、错误数值或仅有无关来源的断言不会被保留。
- 业务概述问题的生成指令优先回答主营业务、产品/服务、制造工艺和销售范围，
  用户未询问规模时不主动展开数字。
- 前端将这类 `insufficient_evidence` 显示为“证据校验未通过”，不再误标成“拒绝或限制回答的原因”。

## 真实资料验证

- “CKIN PET F02 WIFI款饮水机有哪些功能和参数？”返回 `grounded / supported`。2.5L、尺寸、重量、灭菌率和出水模式均通过校验，公开来源摘录只保留直接支持这些断言的原文。
- “请介绍一下公司及三大品牌”首次草稿把 48000㎡/33000㎡ 绑定到了包含另一组面积数据的来源，守卫以 `UNSUPPORTED_MEASURED_VALUE` 阻止输出。强化修正提示后，真实请求返回 `grounded / supported`，仅保留实际支撑公司与品牌断言的 S1、S3。
- 修复后通过公网接口重放“工厂主要做什么业务”，返回 `grounded / supported`，
  `COMPANY_PUBLIC_ALLOWED`，并保留 1 个直接支持来源。
- 修复后通过公网接口重放“公司主要做什么业务？”，返回 `grounded / supported`，
  `COMPANY_PUBLIC_ALLOWED`，并在删除 1 处未通过校验的冗余映射后保留 3 个直接支持来源。
