## 3. 检索与回答验收

| 场景 | 状态 | 检索 | 生成 | 验收点 |
| --- | --- | ---: | ---: | --- |
| 公司、品牌和核心业务介绍 | `grounded` | 90ms | 20.5s | 3 个分节、可见引用、4 阶段分析摘要 |
| 智能喂食器功能介绍 | `grounded` | 77ms | 22.7s | 引用 `ck产品.xlsx` Sheet1 第 2 行等证据 |
| 2027 年营收/净利润 | `insufficient_evidence` | 48ms | 16.5s | 未编造未知财务数据，明确证据不足 |
| 校对后三品牌定位 | `grounded` | 78ms | 23.5s | 正确区分 Gougelila、ChongQin、CKIN PET |

服务端会执行以下输出守卫：

1. Pydantic JSON Schema 校验标题、摘要、分节、状态、意图、置信度和追问。
2. 过滤不在本次召回集合中的来源编号。
3. 当模型没有在正文放置引用时，根据分节与证据的词法相关度补齐可见 `[Sx]`。
4. 来源列表只返回正文实际引用的片段。
5. 可见分析摘要固定展示意图、检索、证据和结论；不返回、不记录原始隐藏思维链。

## 6. 当前边界与下一步

- 当前是可信局域网单机 PoC，默认未启用登录；不得直接暴露到公网。
- SQLite 和进程内检索适合当前 139 个片段，不替代生产级 RAGFlow、审批、版本与审计。
- 单请求生成约 16～30 秒，适合演示和低并发；服务器部署前需做 A10 GPU 基准与并发压测。
- macOS 扫描 PDF 使用 Apple Vision；迁移 Linux 后应切换 RAGFlow DeepDoc、MinerU 或受控 OCR 服务。
- 局域网 IP 由路由器分配，重连网络后可能改变；启动脚本会打印最新地址。
- 下一阶段应由运营复核核心事实条目，建立 30～50 条黄金问题，再决定是否部署到服务器。
