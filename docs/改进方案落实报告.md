## 1. 本轮结果

本轮不是只更新方案文档，而是把高优先级控制点接入了运行链路：

```text
用户问题
  → 确定性回答边界（先于检索和模型）
  ├─ 公司/产品 → 读取审核发布资料 → BGE-M3 混合检索 → 正文 + 逐段来源编号
  └─ 日常养宠 → 直接使用本地模型自身通用知识 → 不检索文档、不返回来源
  → 结构化生成
  → 逐段来源、文本支持、数值和禁止内容校验 → 渲染可见引用
  → 失败时受控修复一次；仍失败则证据不足且不展示来源
  → 固定响应契约与可审计分析摘要
```

当用户同时询问第三方品牌与自有品牌时，系统不再因竞品名称出现而整体拒答。
边界层会先移除第三方对比语义，把问题改写为仅检索和介绍自家产品，并在回答开头
明确告知“该品牌并非本公司或旗下自有品牌产品，因此不作评价或比较”。生成
内容若仍出现第三方信息，则返回只说明自家服务范围的确定性降级回答，不展示
越界内容。所有拒答、限制回答和证据不足回答都通过 `answer.refusal_reason`
返回人类可读原因，页面以“拒绝或限制回答的原因”单独展示。

产品图片请求走确定性媒体链路：系统从原文提取真实图片，按型号、产品类别和页码/工作表
行号匹配，不调用模型生成图片。匹配成功时响应包含 `images[]`，且生成耗时为 0。

服务端不会根据词语相似度猜测并补来源。模型为摘要和每个分节分别返回结构化
`source_ids`；服务端确认编号来自实际上下文、正文与原文匹配且数值受支持后，才统一
渲染可见 `[Sx]`。缺少映射、引用模型未看到的来源、出现来源不支持的带单位数值，或
生成第三方品牌/诊疗内容时，结果不会以 `grounded` 返回。

## 3. 回答边界与固定输出

### 3.1 允许与回避

- 允许：本公司公开信息、Gougelila（狗哥里啦）、ChongQin（宠沁）、CKIN PET；
  非诊疗性质的一般养宠问题由本地模型自身通用知识回答。
- 澄清：无法确认归属的品牌/型号，以及只凭体重要求精确喂食量的个体化问题。
- 回避：其他公司/品牌的介绍、推荐或比较；宠物诊断、药物、剂量、治疗；内部或
  未公开信息；与服务无关的通用任务。
- 急症：固定提示立即联系宠物医院或宠物急诊，不给远程医疗步骤，不推荐产品。
- 混合问题：只生成允许回答的自有品牌部分，并附服务范围说明。

### 3.2 API 响应契约

每次 `/api/chat` 返回以下稳定字段：

```json
{
  "status": "grounded",
  "intent": "company_intro",
  "evidence_status": "supported",
  "decision": {
    "reason_code": "COMPANY_PUBLIC_ALLOWED",
    "policy_version": "2026-09-21.2"
  },
  "answer": {
    "title": "...",
    "summary": "...[S1]",
    "refusal_reason": null,
    "sections": []
  },
  "images": [],
  "thinking_summary": [],
  "sources": [],
  "confidence": null,
  "follow_up_questions": [],
  "metrics": {}
}
```

`thinking_summary` 是系统基于实际执行路径生成的意图、检索、证据和结论摘要，
不包含或伪装成模型的隐藏思维链。固定拒答、澄清与轻量对话不会声称执行过检索。
一般养宠回答使用 `status=general_knowledge`、`evidence_status=model_knowledge`、
`sources=[]`，前端明确显示“模型自身知识 · 无文档引用”。

## 4. 知识库架构与运营流程

### 4.1 两个文档知识域与一个模型通用知识链路

| 知识域 | 用途 |
| --- | --- |
| `company_public` | 公司主体、业务、公开发展信息和品牌总览 |
| `product_public` | 自有品牌、产品、型号、功能、使用说明和公开售后 |

日常养宠不建立文档知识域，也不接受相关文档上传。它只调用本地模型自身知识，输出无
文档引用，并继续经过诊疗、用药、品牌内容、虚假引用和个体化精确喂食量检查。

公开问答的强制过滤条件是：

```text
status=READY
AND enabled=true
AND visibility=public
AND review_status=approved
AND publication_status=published
AND 当前时间在 effective_from / effective_to 内
AND knowledge_domain 属于本次问题允许的知识域
```

### 4.2 运营流程

1. 管理员登录后台并选择“公司公开资料”或“产品资料”。
2. 上传 PDF、XLS、XLSX、CSV、TXT 或 Markdown。
3. 系统解析、分块并建立向量；此时仅为 `draft / pending`。
4. 产品资料在二级详情页绑定品牌和可选产品标识；所有片段以独立卡片展示，可搜索、
   修改或停用。
5. 点击“审核并发布”后才进入公开检索。
6. 修改已发布片段内容后，文档版本递增并自动回到待审核草稿。
7. “重算向量”只处理当前片段，不重新解析原文件，不覆盖运营修改。
8. “撤回”会立即退出公开检索；删除会先把原文件移到 `data/trash/`。
9. 二级页同步展示原文图片；运营可修改图片标题、替代文本、产品标识和聊天展示状态。

本次迁移保留原有 7 份资料与 139 个片段，并补充 74 张原文图片。媒体表迁移前备份为
`data/knowledge.db.pre-media-20260920.bak`；此前的产品归属备份继续保留。

## 5. 后台安全

- 后台 API 默认不再匿名开放；令牌未配置、使用示例占位符或长度不足时返回 503。
- 首次安装脚本自动生成 36 位十六进制随机令牌并写入不入库的 `.env`。
- 管理页登录后只把令牌保存在当前浏览器 `sessionStorage`，不会硬编码进 JavaScript。
- API 使用常量时间比较校验 `X-Admin-Token`。
- 公共聊天页与健康检查不要求管理员令牌；Ollama 仍只监听 `127.0.0.1:11434`。

当前仍是单一管理员令牌，尚未实现多用户、角色权限、会话撤销和完整审计后台；不得直接
暴露到公网。

## 6. 代码和文件规范

### 6.1 模块职责

```text
policies/answer-boundary.yaml   # 业务主体、知识域、固定话术和策略版本
src/company_agent/boundary.py  # 检索前的确定性范围决策
src/company_agent/answer_guard.py # 生成后的证据与禁止内容校验
src/company_agent/retrieval.py # 混合检索和实际上下文集合
src/company_agent/media.py     # WPS/XLSX/PDF 图片提取与原文位置映射
src/company_agent/database.py  # SQLite schema、迁移、发布过滤和审计日志
src/company_agent/services.py  # 用例编排，不承载页面或 SQL 细节
src/company_agent/ollama_client.py # 本地模型协议、结构化生成和一次修复
static/ + templates/           # 无框架局域网前端
templates/document_detail.html # 文档归属与独立片段二级页
static/document_detail.js      # 二级页图片/片段筛选、编辑、审核和产品绑定
tests/                         # 确定性边界、证据和数据生命周期回归
```

### 6.2 工程门禁

- Python 3.11，严格类型检查；公共数据结构使用 Pydantic。
- 格式和导入由 Ruff 统一，行长 100；Mypy 使用 strict。
- 业务规则不得散落到前端；前端只展示服务端状态和决策结果。
- 固定话术进入版本化政策文件；策略变更必须提升 `policy_version` 并补测试。
- 数据库变更采用兼容迁移，禁止为升级清空知识库。
- 新增范围规则至少包含一个允许案例、一个拒绝案例和一个混合/注入案例。
- 引用守卫不得根据相似度推断或补造来源；只允许渲染模型已明确给出且通过逐段校验的来源编号，失败时受控重生成或安全降级。

## 8. 已知限制与下一步

1. 一般养宠使用模型自身知识，可能不完整或过时；前端已明确标识，且不能替代兽医建议。
   医疗、用药、急症和个体化精确喂食量仍在生成前后双重拦截。
2. 当前边界以版本化确定性规则为主，覆盖高风险与常见场景；正式对客前应把方案中的
   B01～B40 做成完整黄金评测，并持续记录误拒和漏拒。
3. 引用守卫能检查来源集合、可见引用、词法关联和带单位数值，但不等同于完整的语义蕴含
   证明；高风险参数仍需人工校对与离线评测。
4. 尚无生产级 RBAC、HTTPS、反向代理、限流、并发队列、流式输出、备份轮换和日志保留
   策略。当前仅适合可信局域网。
5. 上述指标稳定后，再决定是否在服务器上引入 RAGFlow、PostgreSQL/pgvector、Redis 和
   对象存储；本地 139 个片段无需为架构升级而提前增加复杂度。
