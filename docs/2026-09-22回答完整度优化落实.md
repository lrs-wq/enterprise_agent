# 2026-09-22 回答完整度优化落实

## 1. 结论

第二阶段 O05、O07、O08 已在开发目录完成：产品图片按品牌、品类、型号和款式精确匹配；多轮追问会保留最小必要主题状态；非紧急混合问题只生成可独立回答的本公司部分；页面能区分真实回答与安全回退，并把内部技术信息折叠显示。

## 2. 已实施内容

### 2.1 O05：产品身份与图片来源精确关联

- 新增确定性产品身份解析，稳定键格式为 `品牌:品类:型号:款式`。同一资料行中的多个款式会拆成多个明确身份；相同型号的饮水机和喂食器不会只因型号相同而互相匹配。
- 图片查询会强制匹配用户明确给出的品牌、品类、型号和款式。未明确的维度不擅自补成过滤条件。
- 区分纯图片、纯文字和图文组合请求。“看一下参数”不再被误判成只要图片；纯图片请求优先查询已审核媒体目录，不调用生成模型。
- 图片使用独立的 `M1`、`M2` 来源编号，来源直接指向图片自己的文档版本、页码或表格行，不再借用同文档附近的 `S1` 文字片段。
- 返回图片增加 `product_keys`、`document_filename` 和 `source_version`；生成完成前再次确认媒体快照仍处于公开有效状态。

### 2.2 O07：多轮指代与混合问题完成度

- 服务端从最近对话中提取最小状态：主体、品牌、型号、品类、款式、当前任务、歧义和是否为第三方。历史只用于消解指代，不作为事实证据，也不能授予品牌归属或访问权限。
- 支持“它怎么配网”“只比较容量”“WIFI 款呢”“换成 F01 呢”等省略式追问；只改变型号或款式时保留上一轮品类和任务。
- 用户切换到养宠、医疗、隐私、无关问题或寒暄时重新分类，不把上一轮产品主题强行带入。
- 同时出现多个可能对象且没有唯一指代时继续要求澄清，不猜产品。
- 非紧急的“本公司问题 + 医疗问题”会拆分：只回答有公开证据支持的本公司部分，并对诊疗部分给出固定转介；中毒、抽搐等紧急场景仍优先使用急诊提示，不附产品营销。
- 混合品牌和混合医疗的安全改写保留具体型号、款式、品类、所问属性和图片诉求，不再退化成泛化的品牌介绍。

### 2.3 O08：真实回答、回退和页面表达分离

响应增加 `fallback_kind`：

| 值 | 含义 |
| --- | --- |
| `null` | 正常生成且证据验证通过，或真正完成了允许部分 |
| `policy_boundary` | 服务范围或安全边界固定答复 |
| `clarification` | 需要补充主体、型号或上下文 |
| `missing_evidence` | 允许回答但没有形成可验证答案 |
| `service_error` | 服务暂不可用 |
| `scope_only` | 只说明了范围，没有形成实质部分回答 |
| `verified_extractive` | 生成结果未通过守卫，改用已审核原文提取回答 |

- `query_logs` 同步记录 `fallback_kind`，便于统计时把“实质部分回答”和“仅范围说明”分开。
- 页面主标签使用面向用户的状态文案；策略版本、内部原因码、耗时和分析摘要移入折叠的“技术详情”。
- 文字来源与图片来源分开标识，并同时支持 `[S1]` 和 `[M1]` 引用。
- 相同限制不再同时出现在摘要和独立原因卡片；一般养宠明确标为模型自身通用知识、无文档引用。
- 混合医疗在缺少资料或守卫回退时继续使用医疗文案，不会误显示“第三方品牌”原因。
